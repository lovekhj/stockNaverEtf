## 2. 논의하고 결정한 사항

### 2.1 데이터 저장: CSV → DB
- 지금 규모(하루 약 500행)에서는 CSV로도 동작하지만, **날짜를 넘나드는 분석·성과 추적·실시간 감시를 하려면 DB가 필요**하다.
- **Mac mini 단독 운영이면 SQLite로 시작**한다. GitHub Pages에서 어디서든 보거나 Mac mini가 꺼져도 봐야 하면 그때 Supabase로 옮긴다.
- 전환 기간에는 CSV와 DB를 함께 유지한다 (CSV는 PDF·텔레그램·백업용).
- DB에는 표시용 문자열(`"94,900"`, `"+2.04%"`, `"O"/"X"`)을 숫자/boolean으로 변환해 저장하고, 컬럼명은 영문으로 한다.

### 2.2 실시간 감시
- CSV는 **감시 대상을 고르는 용도**, 증권사 API는 **장중에 그 대상만 감시**하는 용도로 나눈다.
- 감시 대상: ① 매수 후보(기본 필터 통과 5~15종목, `추천매수가` 진입·이격도 108% 초과 알림) ② 보유 종목(-3% 손절 3규칙).
- 증권사: **한국투자증권 KIS Developers** 1순위 (Mac 지원, REST+WebSocket, 모의투자 가능).
- **판정 로직은 Python(`monitor.py`)에 둔다.** 브라우저는 백그라운드 탭에서 타이머가 느려져 알림을 놓칠 수 있다. 웹 화면은 결과 표시만 한다.
- **API 키는 `.env`에만** 둔다. 이 저장소는 GitHub Pages로 공개되므로 `app.js`/`index.html`에 키를 넣으면 안 된다.
- Mac mini 운영: 잠자기 방지, launchd 등록, WebSocket 자동 재접속, 외부 조회는 Tailscale.
- 자동 주문은 마지막 단계(모의투자 검증 후).

### 2.3 성과 추적 · 예측
- 매일 선정 종목이 **다음 날 이후 실제로 올랐는지** 누적 기록하고, 거래량·차트 특징과 비교해 새 종목의 결과를 예측하는 것이 목표.
- 진입가는 실제로 체결할 수 있는 가격(**T+1 시가** 또는 오후 4시 시간외 단일가).
- 주 지표: **"N일 안에 +5% 먼저 vs -3% 먼저"** (매매 규칙과 일치).
- 항상 전체 후보 평균·KOSPI와 비교한다.
- `pykrx`로 1~2년 치 과거 데이터를 소급 계산해 표본을 바로 확보한다 (현재 종목 목록 기준이라는 생존 편향 한계는 기록).
- 예측은 조건별 통계표 → (표본이 충분해지면) 로지스틱 회귀/LightGBM, 검증은 날짜 순서대로(walk-forward).

## 3. ⚠️ 알려진 문제

- **캔들 데이터가 실제 데이터가 아님 (최우선).** CSV에 캔들 컬럼이 없어서 `app.js`의 `loadDashboardData`가 **종목코드 홀짝으로 캔들 형태를 임의로 만든다** (`codeNum % 2`, `codeNum % 3`). 기본 필터의 "망치형·아래꼬리" 조건은 지금 사실상 무작위다.
- `app.js`의 `selectDateReport()`는 `index.html`에 해당 화면 요소(`reportPageDateTag` 등)가 없어 호출하면 에러가 난다. 현재 메뉴에서 호출되지 않는 사용 안 하는 코드.
- `app.js`에 `setGradeFilter()`가 두 번 정의되어 있다 (뒤의 것이 적용됨).
- 루트의 `stockDesc1.html`, `stockDesc2.html`은 옛 다크 버전 그대로다. 화면은 `docs/` 쪽을 먼저 읽으므로 영향은 없지만, 정리(삭제 또는 동기화)가 필요하다.
- 일부 CSV 값 형식 오류: 등락률 `--3.22%` 같은 이중 부호.
